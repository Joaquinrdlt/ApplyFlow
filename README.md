# ApplyFlow

ApplyFlow is a job application tracker for keeping roles, progress, and follow-up notes in one place. Create an account, add applications, and update each one as your search moves from application to interview, offer, or rejection.

**Live demo:** [ApplyFlow](https://main.d2zlm9rvcs7zyv.amplifyapp.com/)

## Features

- Sign up, sign in, and sign out with Supabase Auth
- Store applications in Supabase Postgres, scoped to the signed-in user with row-level security
- Add a company, position, status, and notes for each application
- Update an application's status and review application totals by status
- Switch between light and dark themes, with the preference saved in the browser
- Responsive landing page, about page, sign-in form, and application dashboard

## Run Locally

### Prerequisites

- Node.js and npm
- A Supabase project

### 1. Install dependencies

```bash
npm install
```

### 2. Configure Supabase

Create a `.env.local` file in the project root and add your Supabase project URL and anon key (also called the publishable key in newer projects):

```env
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-supabase-anon-key
```

In the Supabase SQL Editor, create the table and user-scoped policies expected by the app:

```sql
create table public.job_applications (
	id bigint generated by default as identity primary key,
	user_id uuid not null references auth.users (id) on delete cascade,
	company text not null,
	position text not null,
	status text not null default 'Applied'
		check (status in ('Applied', 'Interview', 'Offer', 'Rejected')),
	notes text not null default '',
	created_at timestamptz not null default now()
);

alter table public.job_applications enable row level security;

create policy "Users can view their own applications"
	on public.job_applications for select
	using ((select auth.uid()) = user_id);

create policy "Users can add their own applications"
	on public.job_applications for insert
	with check ((select auth.uid()) = user_id);

create policy "Users can update their own applications"
	on public.job_applications for update
	using ((select auth.uid()) = user_id)
	with check ((select auth.uid()) = user_id);
```

### 3. Start the development server

```bash
npm run dev
```

Open the local URL printed by Vite. To run the project checks:

```bash
npm run lint
npm run build
```

## Deployment

The frontend is deployed with AWS Amplify. Amplify builds the Vite application and publishes the generated static site from `dist/`; Supabase provides authentication and the database separately.

Configure `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` in the Amplify app's environment variables so they are available during the build. Because the app handles `/about`, `/login`, and `/dashboard` in the browser, configure an Amplify rewrite so those routes serve `index.html`.

## Implementation Notes

- Supabase Auth manages user sessions; application records include the owning user's ID.
- Row-level security policies restrict reads, inserts, and updates to the signed-in user's records.
- The dashboard reloads application data after creating an application or changing its status; it does not use database realtime subscriptions.
- The app handles `/`, `/about`, `/login`, and `/dashboard` routes in the client. A production host should route these paths to `index.html`.
